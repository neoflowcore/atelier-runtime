# R60 Native Adapter Protocol v001

Status: development candidate; no production publication or installation authorized.

## Execution surfaces

Prefer the user's already-connected native GitHub tools for fresh GET observations and approved writes. A Skill cannot call a connector from Python automatically. Supply the actual connector results to the bundled scripts; do not synthesize responses, credentials, capability receipts or user grants. For an environment with separately authorized existing GH_TOKEN/GITHUB_TOKEN, github_snapshot.py offers an optional GET-only REST transport; never put tokens into a prompt or state file. No redirect, POST, dispatch or paid provider call is supported. Work/Codex/local checkout may support this adapter; Chat may not. Verify each surface separately.

## Trust and release selection

1. A human enrolls an independently obtained publisher public key and exact fingerprint in a private persistent local directory outside the checkout. Use session_state.py DIRECTORY enroll with JSON containing public_key_pem, expected_fingerprint (SHA-256 of exact UTF-8 PEM), minimum_generation. The script never creates a private key and refuses an existing state DB. Do not enroll a key delivered by the registry itself. Establish an external high-water mark for restoration or new devices; deleting/restoring old local state is not safe rollback protection.
2. Read actual main head, commit/tree, registry.v1.json and registry.v1.sig at that commit. Inspect regular file mode and blob identities. Collect signed manifest and modules from exact release commits, verifying content bytes. Recheck main after collection. Native connector callers provide the same snapshot fields as github_snapshot.py; the optional REST transport implements this sequence. Missing or untrusted observations mean READ_ONLY. A signed registry is not permission to mutate a project.
3. Run session_state.py DIRECTORY bind with JSON snapshot and context. context binds run_id, project_sha256, plan_sha256, repository, branch, head, tree. The script stores the monotonic registry generation and exact release pin in one SQLite transaction. Use resume with the same run and freshly verified context; no latest-release substitution. A revoked pin, stale observation, missing DB or drift blocks. State persistence must be demonstrated on the actual host; temporary Chat sandboxes are not durable.
4. For a selected feature, load only manifest-bound files from that immutable release. The control bridge runs on a qualified local/runner checkout and consumes the existing Rev5.2 contracts. It returns an advisory decision, not permission or remote execution.

## Source mutation adapter

The operator/agent must obtain real approval for the exact target, plan, allowed prefixes, expiry and non-destructive development scope before creating any proposal. Run mutation_guard.py with context, actual grant, fresh observation, operation=source.commit, force=false, destructive=false and changes (path, mode=100644, content). The resulting proposal contains expected blob hashes and base HEAD/tree, not a grant. Prefer a single Git tree/commit/ref update. Ref update must be non-force and use a verified expected-HEAD CAS surface; if CAS is unavailable do not mutate. Never write main, publish a registry, delete, merge, modify credentials or incur costs through this path.

Read back actual branch, commit, parent, tree and full base-to-candidate diff. The candidate.files map must include every changed regular file path and its actual blob SHA; reject removed, renamed, symlink, executable-mode or unlisted changes before reconciliation. Supply the actual candidate and observations to mutation_guard.py with mode=reconcile. REMOTE_EFFECT_VERIFIED is conditional on the authenticity of those observations; it never triggers a second write. If the base is observed, recompile only after fresh approval/scope reconciliation; any unknown result blocks blind retry. session_state.py DIRECTORY advance records an independently verified receipt at the expected checkpoint revision. Use a Draft PR only after readback and never auto-merge. Server-side branch/ruleset or a restricted execution adapter must enforce production mutation constraints; this local proposal guard alone cannot prevent another client from bypassing them.

## Publication and field qualification

Build candidate manifest with prepare_manifest.py ROOT .atelier/releases/spec.v1.json. Commit the candidate and verify actual commit/tree/manifest hash, CI and feature tests. A separately authorized publisher prepares a registry generation greater than the external high-water mark, with issue/expiry seconds and the exact candidate commit/tree/hash. Sign exact registry bytes offline with the enrolled key; publish signature and registry atomically through protected review. Never embed a private key, auto-promote a candidate, or change main without final human approval. The empty registry remains intentional until qualification. The same installed bootstrap must bind two signed compatible versions in clean runs, preserve old pins, and block revocation, tampering and replay. Real installation, production enrollment, publication, runtime execution and connector write qualification are separate gates.
