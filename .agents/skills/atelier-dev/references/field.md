# Field probe, surface gate and compatible feature routing

Read this for pre-install qualification or after an explicit request to test the installed candidate. A field candidate is not stable. Never substitute it on normal resume.

- For a separately authorized field probe, read an explicitly pinned registry commit and its exact signed registry bytes, signature and candidate module bytes. The human independently supplies a local trust JSON (channel=field-candidate, distinct enrollment) and expected JSON (channel, registry_head, registry_sha256, candidate entry). The signed registry must have channel=field-candidate and contain just that candidate, with no revocations. Use `scripts/field_probe.py --trust LOCAL_TRUST --expected LOCAL_PIN` with the collected snapshot on stdin. It returns READ_ONLY_FIELD_PROBE only; it cannot authorize project mutations or stable promotion. Normal stable verification rejects this channel. Use separately authorized sandbox tests for writes, never a production run. Candidate source and signed registry commits are distinct. Do not publish a registry or create credentials automatically.
- For normal stable runs, call `scripts/feature_router.py` with actual bound selection, manifest_text, requested feature_id, verified capabilities and verified file texts keyed by path. The handler comes from the signed manifest and must be supported by the installed protocol. Route new feature IDs to existing compatible handlers; unknown handlers are blocked, not executed. Route knowledge as verified text, source proposals/handoffs to local guards, CI evidence to the evidence script, runtime control to a separately qualified checkout, release drafts to the unsigned draft builder. A route neither executes code nor adds authority. New handler types or new tool permissions may require a bootstrap update.
- Before any write handoff, collect fresh actual effective classic branch protection observations for main and the bound development branch, required checks and the exact surface's remote sandbox CAS qualification receipt. `scripts/surface_policy.py` accepts repository, branch, surface_id, observed_at, main_protection, development_protection, required_checks and cas_receipt. Protection observations include repository, branch, HTTP status, source=github.branch_protection and body. CAS receipt includes surface_id, kind=REMOTE_SANDBOX, non_force, stale_expected_rejected, fresh_expected_applied and actual evidence_id. Use these actual observations as surface_evidence in execution_protocol.py. No 403/404, missing rules, guessed bypass restrictions, stale observations or local fixture can qualify production. The conservative classic-protection gate may block a ruleset-only surface until an equivalent qualified adapter exists. This local check is not server enforcement; require actual repository-side controls and human approval. Do not change rulesets or credentials to make a check pass.
- Preserve the original proposal and handoff hash. If authority expires or a write returns an ambiguous result, perform read-only reconciliation with execution_protocol.py mode=reconcile_only and actual proposal, proposal_sha256, handoff_sha256, base_tree, candidate_tree, candidate_commit and fresh_branch. This never emits another write request. Save only independently observed receipts.
