# Runtime-to-native handoff and CI evidence

Read this after verified release binding and before changing a project. Use the actual control bridge output and bound release; never invent either or an approval. The local scripts emit advisory requests/receipts only. Platform approvals and real repository-side controls remain mandatory. The installed Skill cannot call connectors from Python.

1. Collect a fresh branch observation, complete recursive base Git Tree, current user grant, exact change content and actual Runtime control decision. Pass these as `fresh_branch`, `base_tree`, `original`, `control_decision`, `bound_release`, `action_id` and `stage=prepare` to `scripts/execution_protocol.py` via stdin. `original` uses the mutation_guard proposal schema. Retain `proposal_sha256` and `handoff_sha256`.
2. If the native tool schema and current grant permit it, issue the returned create_tree request. Fetch its entire recursive tree at the returned SHA. Re-run with `stage=tree_readback`, `candidate_tree`, commit message and the unchanged proposal and handoff hashes. Only the exact changed regular-file set is permitted. Tree hashes, including nested trees, are recomputed. No workflow, registry, no-op, symlink or destructive changes are allowed through this handoff.
3. After the authorized create_commit request, fetch the actual commit, single parent and tree. Re-run with `stage=commit_readback`, `candidate_commit`, and fresh branch observation. Set `cas_capability=WRITE_VERIFIED` only after the native CAS behavior is actually qualified. The resulting update_ref request requires the exact expected head and force=false. If CAS is unavailable, stop; a plain read-then-write is not CAS.
4. After any ref-update result (including an error), perform fresh branch readback and run `stage=ref_readback`. Never reissue a write from an uncertain result. Save the observed receipt through session_state.py advance only after verifying it came from actual connector reads. Review a Draft PR under the separate applicable scope; do not auto-merge or release.
5. For CI, get the exact run, all jobs for the exact attempt, required step outcomes and complete artifact listing. Pass these to `scripts/ci_evidence.py` as `run`, `jobs`, `artifacts`, `expected` (repository, head, run_id, workflow_id, attempt, required_jobs, required_artifacts), and `archives` (artifact ID to actual base64 archive bytes). Required artifact names must bind run and attempt as run-ID-attempt-N-NAME. Reject unavailable bytes, expired artifacts, digest mismatches, unsafe archives and missing or skipped required steps. Artifact NOT_REQUIRED is different from BYTES_VERIFIED. CI evidence is not a semantic Runtime acceptance or a release grant.
6. When preparing a release, use the repository-side unsigned registry draft builder with the verified candidate manifest, CI receipt and previous verified registry state. Human signing and promotion remain separate. Never auto-enroll a key or trust a key from the remote registry.

If any actual tool, script runtime, durable state, approval or evidence is unavailable, report the specific blocker rather than treating a requested handoff as a completed mutation.
